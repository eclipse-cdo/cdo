Package org.eclipse.net4j.db.dml

Interface SQLStatement

public interface SQLStatement
An immutable adapter-compiled statement definition. Each call to prepare(IDBConnection, ReuseProbability) obtains a statement from the connection's existing cache; the returned statement remains caller-owned and must be released using the normal Net4j DB lifecycle. This definition retains neither connection nor statement. Configured parameter setters are retained through their parameter identities for the lifetime of this definition.

    • bind

      int bind(PreparedStatement stmt, Object... values) throws SQLException
      Binds a sequence of values starting at JDBC position 1. Partial prefixes are allowed and the returned count is the number of bound positions. A single null value must be passed as (Object)null; a null varargs array is invalid. Existing bindings at other positions are unaffected, and callers must account for stale values when reusing statements.
      Parameters:
      stmt - the JDBC statement
      values - values in placeholder order
      Returns:
      the number of values bound
      Throws:
      SQLException - if JDBC binding fails
      IllegalArgumentException - if the sequence exceeds the remaining parameter range
      NullPointerException - if stmt or values is null
      Since:
      4.15

    • bindDefault

      void bindDefault(PreparedStatement stmt, int index, SQLDefaultSetter setter) throws SQLException
      Binds the implementation-defined default for one parameter occurrence at a one-based JDBC index. The setter performs the complete JDBC operation; configured parameter setters and converters are not consulted. This is distinct from binding a supplied value through bindParameter(stmt, index, value), including a supplied null. The default need not be SQL DEFAULT or SQL NULL. If the setter fails, any JDBC side effect it already performed is not rolled back.
      Parameters:
      stmt - the JDBC statement
      index - the one-based placeholder index
      setter - the complete default-value binding operation
      Throws:
      SQLException - if the setter reports a binding failure
      IllegalArgumentException - if index is outside the compiled parameter range
      NullPointerException - if stmt or setter is null
      Since:
      4.15

    • bindDefault

      void bindDefault(PreparedStatement stmt, SQLParameter parameter, SQLDefaultSetter setter) throws SQLException
      Binds the implementation-defined default at every occurrence of a logical parameter identity, in generated SQL order. Matching uses object identity, and each call to the setter receives that occurrence's actual one-based JDBC index. The setter performs the complete JDBC operation; configured parameter setters and converters are not consulted. This is distinct from binding a supplied value through bindParameter(stmt, parameter, value). The default need not be SQL DEFAULT or SQL NULL. If a later setter call fails, earlier JDBC effects are not rolled back.
      Parameters:
      stmt - the JDBC statement
      parameter - the logical parameter identity
      setter - the complete default-value binding operation
      Throws:
      SQLException - if the setter reports a binding failure
      IllegalArgumentException - if the identity is absent from this statement
      NullPointerException - if a required argument is null
      Since:
      4.15
