Class BufferInputStream

java.lang.Object
java.io.InputStream
org.eclipse.net4j.buffer.BufferInputStream
All Implemented Interfaces:
Closeable, AutoCloseable, IBufferHandler
Direct Known Subclasses:
ChannelInputStream
public class BufferInputStream extends InputStream implements IBufferHandler
A buffer handler that defragments the passed buffers into a continuous byte sequence which is exposed as an input stream.

Reading is restricted to one reader thread at a time. Buffers may be supplied concurrently by producer threads, and abort(RuntimeException), close(), and restartTimeout() may be called during a read. Concurrent close never releases a buffer while the reader accesses its contents. Waiting readers are notified when a buffer arrives, the stream is aborted or closed, or the timeout is restarted. Abort is observed at buffer acquisition boundaries, without per-byte checks. This class does not guarantee fairness or producer priority.

A buffer's ownership transfers to this stream when handleBuffer(IBuffer) accepts it. The stream releases it after consumption or closure. A reader that has detached an exhausted buffer releases it after leaving the monitor.

    • abort

      public void abort(RuntimeException cause)
      Aborts this stream and immediately wakes a thread waiting for its next buffer. The first non-null cause wins; later calls do not replace it. Abort is observed at a buffer-acquisition boundary and does not release queued or acquired buffers, which remain owned until consumed or closed.
      Parameters:
      cause - the non-null cause thrown by a waiting or subsequent reader
      Throws:
      NullPointerException - if cause is null

    • read

      public int read() throws IOException
      Returns the next byte, or IOUtil.EOF at end of stream.

      The monitor protects acquisition and access to the current buffer. If this method waits for a buffer, Object.wait() releases the monitor fully, including this method's reentrant acquisition, so producers and lifecycle operations can proceed. An exhausted buffer is detached under the monitor and released afterward.

      Specified by:

    • read

      public int read(byte[] b, int off, int len) throws IOException
      Reads bytes from this stream, acquiring the monitor for at most one buffer per iteration. A read spanning multiple buffers releases the monitor between them so producers and lifecycle operations can proceed. After bytes have been copied, a later timeout or EOS returns the partial result; an exception before any bytes are read is propagated.
