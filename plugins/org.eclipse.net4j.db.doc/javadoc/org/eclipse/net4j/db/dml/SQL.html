Package org.eclipse.net4j.db.dml

Class SQL

java.lang.Object
org.eclipse.net4j.db.dml.SQL
public final class SQL extends Object
Canonical factories for SQL expressions, definitions, references, and fluent statements. Builders preserve their operations as immutable templates; compiling a template renders adapter-specific SQL text and ordered parameter occurrences for preparation and JDBC parameter binding.

A typical SELECT chain keeps schema fields as expressions and parameters explicit: 

 SQL.select(SQL.all(table.as("t")), SQL.count(id).as("total")) //
     .from(table.as("t")) //
     .where(id).eq(SQL.param()) //
     .groupBy(name) //
     .orderByDesc(SQL.count(id)) //
     .build();

literal(Object) values are checked by the selected adapter during compilation and may not be portable across dialects; application values should generally be supplied through param(). SQL comparisons with a literal or bound NULL retain ordinary SQL comparison semantics and are not rewritten to IS NULL.

4.15

    • literal

      public static SQLExpression literal(Object value)
      Creates an expression from an explicit literal value. Compilation supports null, strings, characters, booleans, finite numeric values, and SQL date/time values, subject to validation by the compiling adapter. Other Java types are rejected rather than rendered through arbitrary toString() conversion. Mutable SQL date, time, and timestamp values are snapshotted when this expression is created. Literals such as Boolean or SQL NULL may have dialect-specific semantics; use parameters for portable application values. Comparisons to NULL are not rewritten to IS NULL; use isNull(SQLExpression) or isNotNull(SQLExpression) explicitly.
      Parameters:
      value - the literal value represented by this expression
      Returns:
      the corresponding immutable SQL API value

      4.15
