public class MessageConnector extends SchedulingConnector
Multiplexes logical Net4j channels over an operator supplied asynchronous message connection. The inherited SchedulingConnector scheduler selects buffers from the channels' send queues; this connector advances that scheduled work to an MessageConnector.IMessageConnection provider, which owns the transport and reports asynchronous send completion. A provider may represent either an outgoing client connection or a server-side connection accepted by an independently managed server.

The connector submits at most one send transaction at a time. Scheduler completion means that a selected channel's queue head has been consumed by the connector; provider acceptance is a separate event, and an accepted buffer remains pinned until the provider's terminal callback proves that it no longer accesses the storage. The send pump serializes this progression without creating another queue or scheduler. A rejected send retains no provider borrow and waits for a writable notification before retrying.

Incoming messages use one unit of provider demand at a time. Accepted frames enter a connection-ordered ingress queue, then per-channel serial queues so a blocking handler on one channel does not stall another. Receive demand is replenished after ingress acceptance, independently of handler completion and buffer release. The connector retains provider storage without copying within a per-activation byte budget, then copies under a second byte budget; exhausting both fails the connection. Activation generations identify callbacks and send records belonging to a particular provider binding, so stale callbacks cannot advance a later connection. Shutdown detaches accepted sends but cannot reclaim their buffers until terminal completion; aborting a connection does not itself end a provider's borrow.

    • MessageConnector

      public MessageConnector(long zeroCopyReceiveBudgetBytes, long copyReceiveBudgetBytes)
      Creates a message connector with bounded per-activation receive storage budgets.

      The default budgets allow one megabyte of outstanding zero-copy storage and four megabytes of copied receive storage per connection. When the zero-copy budget is full, incoming messages are copied while copy budget remains. Exhausting both budgets fails the connection.

      Parameters:
      zeroCopyReceiveBudgetBytes - maximum bytes retained from provider-owned receive storage
      copyReceiveBudgetBytes - maximum bytes retained in copied receive storage
      Throws:
      IllegalArgumentException - if either budget is negative
      Since:
      4.23

    • terminatePendingActivation

      protected final void terminatePendingActivation()
      Ends a deferred activation when its owner explicitly aborts the provider connection. The method arbitrates against readiness and negotiation completion, detaches the current provider generation, and completes the lifecycle attempt as failed. It is safe to call after a provider has already reported closure and does not depend on MessageConnector.IMessageConnection.abort() producing a callback.
      Since:
      4.23
