Interface SQLParameterBinder

public interface SQLParameterBinder
A mutable cursor that binds successive values to one prepared statement using one compiled statement. Each cursor has an independent position. Failed operations leave the cursor at its starting position, although JDBC effects from earlier values in a failed sequence may already have occurred. The compiled statement remains immutable and does not retain cursors. Callers are responsible for positions and stale JDBC parameter values when they bind only part of a reused statement.
Since:
4.15
Author:
Eike Stepper

    • bind

      SQLParameterBinder bind(Object... values) throws SQLException
      Binds a sequence at the current position and advances after the whole sequence succeeds. The full range is validated before JDBC is changed. A converter or JDBC failure leaves the cursor position unchanged, although earlier JDBC positions in the sequence may already have been bound.
      Parameters:
      values - values in placeholder order; a single null value is passed as (Object)null
      Returns:
      this cursor
      Throws:
      IllegalArgumentException - if the sequence exceeds the remaining parameter range
      NullPointerException - if values is null
      SQLException - if a converter or JDBC setter fails
      Since:
      4.15

      SQLParameterBinder bindParameter(SQLDefaultSetter setter) throws SQLException

    • skip

      SQLParameterBinder skip()
      Advances this cursor by one parameter position without binding that position. The same cursor is returned. Skipped positions remain unbound by this call and may retain old values when the prepared statement is reused; use another binding operation to provide their values. Unlike from(int), this operation only moves forward. The final valid position is parameter count plus one; skipping from it is invalid.
      Returns:
      this cursor
      Throws:
      IllegalArgumentException - if advancing would move past the final valid position
      Since:
      4.15

    • skip

      SQLParameterBinder skip(int count)
      Advances this cursor by a nonnegative number of parameter positions without binding or clearing those positions. A zero count is a valid no-op. The same cursor is returned. Positions skipped this way must be bound separately if they need values; a reused prepared statement may retain previous JDBC values. This relative forward movement is distinct from the absolute repositioning, forward or backward, provided by from(int). The destination may be the final valid position, parameter count plus one, but not beyond it.
      Parameters:
      count - the nonnegative number of positions to skip
      Returns:
      this cursor
      Throws:
      IllegalArgumentException - if count is negative, overflows the valid range, or moves past the final valid position
      Since:
      4.15
