Repository Services and Events

  

Author: Eike Stepper

A repository is a running service object. Its managers expose server-side state; its containers and lifecycle notifiers expose meaningful changes. Observe those services from an application extension and unregister every listener at shutdown.

1 Services
2 Sessions, Views, and Transactions
3 Event Families

1  Services

IRepository.getSessionManager() exposes active sessions. The branch, revision, and commit-info managers (CDOBranchManager, CDORevisionManager, and CDOCommitInfoManager) provide repository history services. The package registry (CDOPackageRegistry), locking manager, and optional unit manager complete the commonly useful services. Inspect their capability and lifecycle contracts instead of assuming that every store supports every historical or branching operation.

2  Sessions, Views, and Transactions

An ISession is the server-side representation of a client session. Its manager owns the session, and the session owns server views; ITransaction is the transaction form of a view. They carry server-visible user, session, view, branch-point, and repository context. Applications may inspect that context and use it in supported handlers, but should not retain closed sessions or invoke internal commit machinery.

3  Event Families

Repository and container lifecycle events identify activation and removal. The session manager emits container events for session open and close; each session emits container events for views and transactions. Commit-info handlers observe completed commit information. Branch and locking managers have their own notifier contracts. Listener callbacks run in the notifier's execution path; keep them quick and hand off slow work instead of making unsupported assumptions about a global callback thread.

ObserveSessions.java      
IListener listener = event -> {
  repository.getSessionManager().getSessions();
};

repository.getSessionManager().addListener(listener);
return listener;
